# Issue Analysis: Tool Workflow Blockers

## Problem 1: Lint Validation Blocking Progress

### Issue Description
When moving task 123 from PROGRESSING to TESTING, the tool failed with:
```
Error: Validation failed. Fix errors before proceeding.
```

The lint error was in a pre-existing file (`tests/test_all_transitions.py:21`) unrelated to the changes made.

### How to Reproduce
1. Make a small change (e.g., fix `--help` handling in `repo.py`)
2. Move task from BACKLOG → READY → PROGRESSING (successful)
3. Attempt to move to TESTING
4. Tool runs validation and fails due to pre-existing lint errors in other files

### Better Approach
The tool should:
1. **Validate only changed files**: Run lint only on files that were modified in the current branch, not the entire codebase
2. **Allow override for pre-existing issues**: Provide a flag like `--skip-validation` or detect pre-existing errors vs new errors
3. **Show clear error context**: Indicate which files/errors existed before the branch was created vs new errors

## Problem 2: Criteria Format Issues

### Issue Description
When setting criteria using:
```
hammer tasks modify <id> --criteria "value1" "value2"
```
The values get wrapped with markdown checkboxes incorrectly.

### How to Reproduce
1. Create a task with criteria
2. Modify criteria using quoted strings
3. Check the result - it shows `- [ ] - [x] value1` instead of `- [x] value1`

### Better Approach
The tool should:
1. **Detect existing checkboxes**: If a criteria value already starts with `- [ ]` or `- [x]`, don't add another checkbox
2. **Normalize input**: Accept both formats:
   - `--criteria "value1" "value2"` → `- [ ] value1`, `- [ ] value2`
   - `--criteria "- [x] value1"` → preserve exact format
3. **Document expected format**: Update help text to clarify criteria format

## Problem 3: Workflow State Transitions

### Issue Description
Task 123's code was already merged to main/testing, but the tool couldn't progress it through the state machine due to validation errors.

### How to Reproduce
1. Make changes and merge to main via git directly
2. Try to move task through workflow states
3. Validation fails because the tool expects to run on uncommitted changes

### Better Approach
The tool should:
1. **Detect merged state**: Check if branch is already merged to main/testing
2. **Allow skip for merged tasks**: Progress directly to DONE/ARCHIVED for already-merged work
3. **Sync task state with git**: Auto-update task state when branch is merged

## Recommendations

### Short-term Fixes
1. Add `--skip-validation` flag for already-validated work
2. Fix criteria parsing to handle existing checkboxes
3. Add `git status` detection to skip validation when branch is clean

### Long-term Improvements
1. Track pre-existing lint/errors at task creation time
2. Validate only staged/committable changes
3. Add `--already-merged` option to skip workflow gates
