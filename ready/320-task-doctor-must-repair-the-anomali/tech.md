Task 314 removed the guard's warning tier: all eight GUARD_* codes (DUPLICATE_ID, DUPLICATE_REMOTE_ID, BRANCH_NONCONFORMANT, BRANCH_MISSING, STATE_DUPLICATE, REMOTE_DIVERGENCE, WORKTREE_ORPHAN, WORKTREE_MISSING) now REJECT every pipeline transition. These split into two classes. (1) Metadata/cosmetic drift: metadata.Id/Br/St mismatch, wrong directory name, wrong state folder, stale counter — unambiguous, repairable in place, already handled by tasks_ai/commands/doctor.py. (2) Structural anomalies: two branches or folders claiming one id, nonconformant/missing branches, divergent remote refs, orphaned worktrees — the correct target is ambiguous, and any auto-repair must silently pick a winner and discard the loser, reintroducing exactly the data-merging corruption the strict guard was built to make impossible. Policy (breaking change): corruption becomes impossible going forward; repos with unrecoverable structural anomalies are abandoned and recreated fresh. That migration path is separate work (plan-cleanup.md triage) and is NOT part of this task. Doctor therefore reports structural anomalies read-only with actionable hints, and --fix repairs only the safe class. Currently doctor.py reports nothing about guard codes, so the user must discover the blocking reason by running guard scan separately.
