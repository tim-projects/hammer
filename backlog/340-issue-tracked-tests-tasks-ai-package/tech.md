tests/tasks_ai is a TRACKED snapshot of an old package layout (git ls-files tests/tasks_ai shows __init__.py, audit.py, cli.py, commands.py, ... no context.py). It was committed by accident early in the repo's history and has never been removed.

Why it breaks: pytest's default import mode inserts the test file's basedir (tests/) at the FRONT of sys.path, before the project root. 'import tasks_ai' then resolves to tests/tasks_ai, which lacks every module added since the snapshot (context.py, store_lock content, guard_engine-era helpers). Consequences seen live during task 336: any test importing tasks_ai at module level or in a function crashed with ModuleNotFoundError, while running the same test file standalone with cwd=repo root passed - a confusing environment-dependent failure. The current workaround (sys.path.insert(0, PROJECT_ROOT) inside tests) is repeated per test file and will be forgotten.

Fix direction: (1) git rm -r tests/tasks_ai (deletion beats addition; it is dead weight - nothing imports it on purpose), and (2) add one small conftest.py at the repo root that inserts the project root at sys.path[0], so every test gets deterministic resolution without per-file hacks, plus (3) a regression test asserting tasks_ai.__file__ is under the project root and NOT under tests/. Verify first that no test or tool legitimately reads the tests/tasks_ai copy (grep tests/ and tasks_ai/ for 'tests/tasks_ai' or relative copies of the package).
