repo.py find_project_root only recognizes a .git directory. In a linked Git worktree, .git is a file, so the search climbs to the main repository, whose .tasks directory is found first. All repo git operations therefore run in main rather than the invoked task worktree. The observed result was hammer repo commit staging an unrelated root .tasks-repo directory as a gitlink and committing it to main. Fix repository-root resolution using git rev-parse --show-toplevel from the invocation directory, with the existing directory walk only as a non-Git fallback. Also prevent the throwaway .tasks-repo directory from being staged by gate or wrapper commits, without deleting a user's existing directory.
