As an operator running parallel agents against the central .tasks store, I need tasks move to commit only the moved task's own paths, so another agent's uncommitted record is never swept into my move commit and the store is left clean afterwards. Today PostMoveCommitHook runs 'git add -f .' in tasks_path, which stages every pending change in the shared store under 'Mv <task>' and leaves .ops/staging/<task> plus old-state-folder deletions pending after the physical move, so the store never reaches a clean state and the next store-wide add sweeps them up under the wrong task.
