Production currently permits absolute tasks_dir overrides and only rejects a store inside the current task worktree. store_is_git uses git rev-parse --is-inside-work-tree, so a plain .tasks directory inside a parent repository is mistaken for an independent store and commit_task_paths advances the code default branch. The fix must canonicalize production paths, require .tasks to be its own Git top-level, detect .tasks in every registered task worktree, prevent task branches from materializing .tasks, and fail without silently deleting local records.
