Verified root cause (three parts): (1) check.py get_tool reads repo.lint/repo.test/repo.type_check/repo.format from the store config, which in this repo is /home/vscode/git/tasks-ai/.tasks/config.yaml and carries absolute paths (lint/test/type_check/format = /bin/true), while TOOL_COMMANDS only maps tool NAMES (ruff, pytest, pyright, true) - so a path value resolves to None and every check aborts with 'Tool X (None) not configured or not supported'. (2) find_project_root() in check.py walks up looking for a .tasks dir or a .git dir, but a task worktree's .git is a FILE, so from any .task-worktrees/<branch> directory it resolves to the MAIN repo root and loads the main store config; a worktree always fails while main always succeeds. (3) on main, tasks_ai/check_wrapper.py short-circuits with 'Codebase unchanged, skipping validation' when .last_validation_hash matches, so the abort is invisible exactly where it should have been caught. Fix: accept a command path as a tool (or normalise the store config to tool names), and make find_project_root detect a worktree .git file so a worktree is its own project root.
