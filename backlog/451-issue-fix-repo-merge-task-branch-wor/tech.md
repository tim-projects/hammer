The legacy generic merge fallback in `repo.py` parses the source branch as a task only. For other source/target combinations, including `main` to a task branch, `cmd_merge` changes the main worktree to the source and destination branches. This fails when the destination task branch is already checked out in a registered task worktree because Git does not allow the same branch to be checked out in multiple worktrees. The newer worktree-aware implementation already provides `WorktreeManager` and `GitService.sync_worktree`, and `tasks move ... PROGRESSING` uses that path. The fix must preserve the existing gated task-branch-to-pipeline promotion behavior while making the generic fallback worktree-aware for task-branch destinations.
