Root cause of the naming ambiguity behind the task-344 worktree incident: tasks_ai/commands/create.py:93 builds task_id as f'{numeric_id}-{task_type}-{clean_title[:30]}' and the same 30-character slug cut is duplicated verbatim in tasks_ai/commands/create.py:192 (the pairing id for --parent), tasks_ai/commands/doctor.py:130 (expected Br) and tasks_ai/commands/doctor.py:170 (expected directory name). Because create truncates and doctor re-derives with the identical cut, the branch, task folder and worktree basename stay equal to each other (worktree_manager.py:103 joins worktrees_base + branch) - but all of them are a truncated form of the title slug, with nothing in the output saying so. Anything that spells the name from the title instead of the store gets a different string, and that mismatch is what silently produced a stray directory during task 344. Four copies of one rule also means a change to the naming policy has to land in four places or doctor starts repairing names 'incorrectly'.
