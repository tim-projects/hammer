Root cause: WorktreeManager.remove_task_worktree removes the registered worktree before calling GitService.is_merged(branch). is_merged selects the default branch through get_default_branch(), whose Git command defaults to context.repo_root; when the CLI is launched inside that task worktree, this path has just been deleted and subprocess.run raises FileNotFoundError. Other merge-check commands already use context.main_repo_root. Smallest safe fix: evaluate is_merged before removing the worktree, then remove the worktree and delete the branch using explicit main_repo_root cwd. Regression must exercise cleanup with context.repo_root equal to the registered worktree path and assert successful worktree/branch cleanup.
